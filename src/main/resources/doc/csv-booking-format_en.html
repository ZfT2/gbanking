1. Basics

The file is UTF-8 encoded and uses a semicolon as separator. The first row contains field names. Additional columns unknown to GBanking are not required; known columns may appear in any order.

  • Amounts may use comma or dot as decimal separator. Grouped values such as 1.234,56 and 1,234.56 are also recognised.
  • Dates are accepted as DD.MM.YY, DD.MM.YYYY or ISO date YYYY-MM-DD.
  • Whitespace at the beginning and end of a field is removed.

2. Required fields

FieldDescription
BUCHUNGSDATUMTransaction booking date; every data row must contain a value.
BETRAGTransaction amount. Negative values are expenses; positive values are income.
VERWENDUNGSZWECKTransaction purpose text; every data row must contain a value.
KONTO_IBAN, KONTO_NR or KONTO_NAMEAt least one of these columns is required when import is not started from an account context menu.

4. Effect on the address book

GBanking creates or enriches an address-book contact from the EMPFAENGER_* fields. It uses the same recipient logic described in the manual: existing contacts are found mainly by IBAN or account number, compatible data is reused and unused duplicates may be updated.

If an imported contact has no bank name, GBanking may obtain it from the BIC, bank code or the bank code embedded in a German IBAN. Different known bank names are not merged without verification. Contacts already linked to historical online/import transactions or payment orders remain protected.

Recommendation: Include the IBAN as well as the name whenever possible. It provides the most reliable matching and avoids unnecessary duplicates.

6. Example: minimal file for account-context import

When import is started from an account context menu, account matching fields may be omitted. If the file still contains account fields, they must match the selected account.

BUCHUNGSDATUM;BETRAG;VERWENDUNGSZWECK
10.04.2026;25.00;Cash deposit

7. Practical tips

  • Export a few existing transactions as CSV when you need a reliable template containing every field name.
  • When using a spreadsheet application, explicitly open and save the file as UTF-8 with semicolon separators.
  • Check signs, date formats and account matching with a small test file first.
  • CSV files are not protected by tenant encryption. Delete or encrypt confidential exchange files after use.
